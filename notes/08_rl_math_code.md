# 专题：为什么数学和代码的 RL 能提升推理

支撑 S13–S21。这一节是全场的高潮，需要把"显著提升逻辑水平"拆成可解释的机制，而不是一句结论。

---

## 1. 先把"推理"说清楚

在模型语境里，"推理"不是神秘能力，而是四种可观察的行为：

1. **分解**：把大目标拆成子目标；
2. **维持约束**：多步之间不丢失条件；
3. **验证**：检查中间结果；
4. **回溯**：发现错了能改。

这四件事都可以被训练，也都可以被评测。报告里用这个定义，能避免"智能"这种无法证伪的词。

---

## 2. RL 的基本循环

```
策略（模型） → 采样轨迹 → 奖励 → 更新策略
```

- 策略：给定当前状态，决定下一个 token。
- 轨迹：一次完整的解题过程。
- 奖励：对结果的评分。
- 更新：提高高奖励轨迹的概率。

RLVR（RL with Verifiable Rewards）的关键：**奖励由程序给出，不由人给出**。

---

## 3. 为什么数学和代码是理想环境

| 条件 | 数学 | 代码 |
|---|---|---|
| 对错可自动判定 | 答案匹配 / 证明检查 | 单元测试 / 编译 |
| 可无限生成 | 改参数、改条件 | 改输入、改约束 |
| 难度可调 | 算术 → 竞赛 | 练习 → 竞赛 |
| 反馈即时 | 对 / 错 | 报错信息、测试失败位置 |
| 无需人工标注 | 是 | 是 |

对比开放域写作：没有标准答案，只能靠人类偏好，成本高、噪声大、容易被奖励模型攻破。

一句话：**RL 最怕奖励稀疏且不可靠；这两个领域恰好相反。**

---

## 4. 代码 RL 练的四个机制

### 4.1 分解

写代码必须先拆函数、拆模块、拆边界条件。这个习惯迁移到证明，就是拆引理。

### 4.2 验证

测试是显式的验收标准。模型学会"写完先跑一下"，而不是写完就交。

### 4.3 调试

编译器和测试给出**定位到行**的错误信息。这是比"对/错"更稠密的信号，直接教模型如何回溯。

### 4.4 长程约束

变量作用域、类型、控制流要求模型在多步之间维持状态。这正是"逻辑"最核心的部分。

> 这四件事合起来，就是"先写步骤、再检查、错了就改"的行为模式。它在数学、代码、乃至一般规划任务之间是可迁移的。

---

## 5. 数学与代码的分工

| | 数学 RL | 代码 RL |
|---|---|---|
| 主要训练 | 演绎、精确性、证明结构 | 构造、调试、工程约束 |
| 奖励 | 答案 / 证明检查 | 测试 / 编译 |
| 迁移方向 | → 代码、逻辑题 | → 数学、规划 |
| 弱点 | 容易过拟合题型 | 容易奖励黑客（写死测试） |

实践中常混合使用，比例本身就是一个研究问题。

---

## 6. 一条典型的训练管线

```
1. 冷启动 SFT      用少量高质量解答教会格式
2. 拒绝采样        每题采样 k 条，保留通过验证的
3. RLVR            用 GRPO/PPO 在可验证奖励上优化
4. 专家迭代        用搜索产生更难的成功样本，回到 3
5. 课程学习        从易到难，维持正奖励比例
6. 推理时扩展      多采样、树搜索、自洽性投票
```

关键参数：采样温度、每题采样数、奖励严格度、课程难度曲线。

---

## 7. 证据与边界

### 观察到的现象

- 代码 RL 之后，数学与通用推理 benchmark 提升；
- 数学 RL 之后，代码生成也提升；
- 混合训练通常优于单一领域。

### 必须打的折扣

1. **污染**：benchmark 题目可能出现在预训练语料里。
2. **评测选择**：只报涨的指标。
3. **定义模糊**："推理能力"没有统一定义。
4. **分布外**：换一个领域，迁移幅度会掉。
5. **奖励黑客**：模型可能学会通过测试而不是解决问题。

### 诚实的结论

> RL 训练的是"在可验证任务上搜索与纠错"的技能。它在相邻领域可迁移，但不等于通用智能。

---

## 8. 四个常见误解

| 误解 | 实际 |
|---|---|
| RL 能教模型新知识 | 主要是重加权已有能力、塑造行为 |
| 思维链越长越强 | 长链可能只是重复或绕圈 |
| benchmark 涨 = 更聪明 | 可能只是更会考试 |
| 算力够就行 | 奖励设计、数据质量、课程才是瓶颈 |

## 10. 一句话总结

> 数学和代码之所以能提升推理，不是因为它们"高级"，而是因为它们**对错便宜、可以无限练、错误信息具体**——这让"试错"第一次变成了可规模化的训练信号。
