## 0. 开场（1'）

**目的**：用一个可计算的小问题，把"文字"和"token"分开。

**做法**：

1. 投一句话：`Celestial mechanics is the poetry of orbits.`
2. 问：这句话模型看到的是什么？
3. 揭示：10 个 token，10 个整数。
4. 中文对照：《天体力学基础》的"本书系统地介绍了天体力学"，12 个字 → 10 个 token、10 个整数。

**核心信息**：今天从最小的单位讲起，一路讲到"下一个定理"。

---

## 1. Token（5'）

**核心信息**：

- token 是子词切分的结果，不是字，也不是词
- 词表是一张固定的「片段 → 整数」映射表，训练前定好
- token → 整数 ID，模型只处理整数和向量
- "模型 token / 计费 token / 认证 token"是三个东西，只是重名
- 上下文窗口、价格、数数出错，全部由 token 决定

**页面**：

1. 一句话被切成 token（中英混排，实测数据）
2. 词表：行号 = ID、规模标尺
3. 用量：2.85 亿 token、2,599 次请求、27 元
4. 价格：缓存命中 vs 未命中，差一个数量级
5. 文字 → ID → 向量（embedding）

**过渡**：

> 知道了输入长什么样，接下来看它怎么被处理。答案比想象中简单：一个函数。

---

## 2. 模型（5'）

**目的**：用李宏毅课程式的讲法，一句话讲清内部，不展开结构。

**核心信息**：

- 模型就是一个函数：输入 token 序列，输出下一个 token 的概率分布
- 中间是 Transformer，本质是一堆矩阵运算，今天不展开
- 采样：从分布里取一个 token，接回输入，再算一次
- 无状态：每次调用独立，记忆靠外部

**页面**：

1. 输入 → 概率分布（Transformer + softmax）
2. 采样：贪心 / 按概率 / temperature
3. 采样算法：累积分布 + 随机数 u
4. 无状态：模型没有记忆

**过渡**：

> 这个函数不是天生的，它是被三个阶段训练出来的。

**明确不讲**：embedding 维度、attention 公式、MLP、残差、位置编码、KV cache 细节。全部放备份页。

## 3. 训练（11'）

**目的**：全场最长、最重要的一段。

**核心信息**：

- Pretrain 和 SFT 都可使用下一个 token 预测目标；本例 SFT 只对 answer token 算 loss，强调示范行为，也可能学习任务相关信息
- RL 换了目标：不再模仿，而是最大化奖励；一句话：在环境里试错，用奖励信号调整策略，让长期回报最大
- RLVR 的关键：奖励来自程序，不来自人
- 数学与代码是理想的 RL 环境：可验证、可生成、可调难度
- 代码 RL 训练的是分解、验证、调试、长程约束——这正是"逻辑"的操作定义

**页面**：

1. 从预测到解题：知识 → 行为 → 策略
2. Pretrain：交叉熵 + 数据 / 算力
3. 前 20 个 token：分词、前缀、目标（《天体力学基础》）
4. 这个 loss 是什么：负对数似然 / 交叉熵
5. 压缩即智能
6. SFT：看标准答案学做事（只对 answer 算 loss）
7. 三种角色：system / user / assistant
8. 它到底怎么预测：逐 token 采样
9. 什么是强化学习：一句话定义 + 状态 → 动作 → 奖励
10. RL 的老战场：Atari / AlphaGo / Dota / StarCraft；AlphaFold 不是 RL（监督学习）
11. RL 的新战场：做题，对答案；strawberry 例子 + o1/R1（DeepSeek moment）
12. RL 的常见算法：PPO / GRPO / RLOO / DPO
13. 数学/代码的天然优势：反馈 + 四个机制

**过渡**：

> 训练完只是一个函数。真正干活，要靠我们怎么用它。

## 4. 使用（14'）

**核心信息**：

- prompt 是条件化，不是编程；加内容就是改条件概率
- context 是有限预算；大海捞针说明"窗口大 ≠ 找得到"
- CoT 负责言语/逻辑推理；精确算术交给程序
- CoT 把隐式推理摊成显式步骤；pruning 控制思考预算
- tool calling 把计算与行动交给程序
- agent loop 把状态放到外部；memory 是产品，system 不是沙箱

**页面**：

1. 从会说话到会干活
2. 2023：从补全到对话
3. Prompt：用内容改变分布
4. CoT：把思考写出来
5. Context window 的膨胀（2k → 1M）
6. Context 是有限的（大海捞针）
7. Context engineering：怎么放
8. CoT pruning
9. Tool calling：算不准，就交给程序
10. Agent loop
11. Memory：信号与噪声
12. S36：代码产出激增，人的审查能力成为卡点；区分 Anthropic monorepo 落地变更与 Claude Code 仓库合并 PR
13. S37：系统接住常规审查——运行证据、AI 复核、安全与自动测试、发布回滚；规则文件提供上下文
14. S38：人的注意力按风险分配——可信作者、审批边界与明确责任
15. S39：失败成为评测资产——同时衡量漏检、误报与轮数，设置升级处理条件
16. S40：把模型放回系统里（总图）；模型提议，系统组织上下文、状态、工具与检查

**过渡**：

> 这是一个具体的工程参考例子，具体科研流程由同行判断。接下来看 AI × math 的公开进展。
