## 0. 开场（1'）

**目的**：用一个可计算的小问题，把"文字"和"token"分开。

**做法**：

1. 投一句话：`Celestial mechanics is the poetry of orbits.`
2. 问：这句话模型看到的是什么？
3. 揭示：10 个 token，10 个整数。
4. 中文对照：《天体力学基础》的"本书系统地介绍了天体力学"，12 个字 → 10 个 token、10 个整数。

**核心信息**：今天从最小的单位讲起，一路讲到"下一个定理"。

## 1. Token（5'）

**核心信息**：

- token 是子词切分的结果，不是字，也不是词
- 词表是一张固定的「片段 → 整数」映射表，训练前定好
- token → 整数 ID，模型只处理整数和向量
- "模型 token / 计费 token / 认证 token"是三个东西，只是重名
- 上下文窗口、价格、数数出错，全部由 token 决定

**页面**：

1. 一句话被切成 token（中英混排，实测数据）
2. 词表：行号 = ID、规模标尺
3. 用量：2.85 亿 token、2,599 次请求、27 元
4. 价格：缓存命中 vs 未命中，差一个数量级
5. 文字 → ID → 向量（embedding）

**过渡**：

> 知道了输入长什么样，接下来看它怎么被处理。答案比想象中简单：一个函数。

## 2. 模型（5'）

**目的**：用李宏毅课程式的讲法，一句话讲清内部，不展开结构。

**核心信息**：

- 模型就是一个函数：输入 token 序列，输出下一个 token 的概率分布
- 中间是 Transformer，本质是一堆矩阵运算，今天不展开
- 采样：从分布里取一个 token，接回输入，再算一次
- 只会预测：唯一动作是 next-token；记忆、计算、工具、计划都在外部

**页面**：

1. 输入 → 概率分布（Transformer + softmax）
2. 只会预测：模型只给下一个 token，不保存状态、不执行计算

**过渡**：

> 这个函数不是天生的，它是被三个阶段训练出来的。

**明确不讲**：embedding 维度、attention 公式、MLP、残差、位置编码、KV cache 细节。全部放备份页。

## 3. 训练概览、奖励与问题求解（14'）

**目的**：用熟悉的任务讲清反馈与学习，把 loss、梯度、mask 和算法名词留在备份中。

**页面与叙事**：

0. **第 2 页 · 全景导航**：六个章节卡片可直接点击跳转；小标签直达关键页（GRPO 公式、REFLEX、Claude Code、系统总图等）。
1. **第 10 页 · 训练：预训练与后训练**：先分两个阶段；后训练介绍 SFT 与 RL，并突出 RL 是接下来的重点。
2. **第 11 页 · RL：行动、结果与反馈**：观察环境 → 采取动作 → 得到结果 → 反馈/奖励 → 改进策略；先讲宏观循环，调整的是动作选择策略。
3. **第 12 页 · 著名游戏案例**：Atari DQN（2015 论文）、AlphaGo（2016）、OpenAI Five 与 AlphaStar（2019）；RL 根源更早，不把游戏当起点。
4. **第 13 页 · 一个分数怎样教会策略**：打砖块的尝试、结果与延迟收益；环境可执行，能反复尝试。
5. **第 14 页 · GRPO 目标函数**：DeepSeekMath 目标；组内采样、逐 token 平均、概率比 ρ、裁剪、KL 正则；给出 Â 的组内标准化定义与完整出处。
6. **第 15 页 · GRPO 机制**：同一问题采样一组回答，逐个评分；示例 G=4 展示组内竞争与优势；正优势提高概率、负优势降低；无需 critic。
7. **第 16 页 · REFLEX**：电商 Query 扩展的搜索引擎在环训练；相关性 + 覆盖奖励、格式闸门；SFT 预热 → GRPO；论文消融展示 GRPO 的决定性增益。
8. **第 17 页 · 数学与代码的共性**：外部环境相对封闭（数学：公理化系统；代码：语言规范与运行环境），错误可逐步追溯并定位，数据结构清晰、便于筛选。RL 改进策略，更多算力用于生成候选与并行验证；穷举结论保留有限、有解、可靠判定与成本条件。
9. **第 18 页 · 共享推理与迁移**：数学 RL 提升代码表现（AceReason）；代码训练提升状态追踪（Kim et al.）；迁移依训练方法、配比与评估任务。
10. **第 19 页 · Coding agent 的行动场所**：读文件 → 修改 → 执行 → 反馈；Claude Code 等是具体例子，不能写成代码 Agent 或代码 RL 的历史起点。
11. **第 20 页 · 四类任务，不同的反馈条件**：编程、数学、产品设计、交易同页比较；可检查的目标让算力能用于系统搜索和候选筛选，穷举的确定性结论保留有限、有解、可靠判定的条件；不使用 Kepler 周期奖励示例。
12. **第 21 页 · 正确与优秀**：语法、定义与检查让数据更可组织；数学和代码都追求优雅、清晰与有用，语料仍需筛选。
13. **第 22 页 · 总结：环境、反馈与参数更新**：良好定义的问题 → 放进环境 → next-token 预测 → 检查与追溯 → 定义 loss → 反向传播迭代 → 能力提升。备注区分监督学习的直接反向传播与强化学习的策略梯度目标。
14. **第 23 页 · 模型只会预测下一个 token**：前文 → 模型 → 下一个 token 概率 → 采样；对话历史由客户端重发；算术是记忆与模式补全；工具与计划在模型外。

**过渡**：

> 对可以反复尝试并检查的任务，我怎样组织实际工作的循环？

## 4. 使用（8'）

**核心信息**：

- context 是有限预算；大海捞针说明"窗口大 ≠ 找得到"
- 一页合并：窗口有限、Context engineering 决定放什么、Memory 决定留什么
- tool calling 把计算与行动交给程序；工具输出仍是不可信输入
- harness 管权限、沙箱、超时、验证、回滚与停止
- 系统图把 Memory + Tool + Harness 收束成 Agent 系统
- skill 把流程、脚本与参考资料封装成可复用能力

**页面**：

1. 第 24 页：训练之后的四个短板——不保存状态、Context 有限、计算是记忆与模式补全、输出是概率；对应 Context/Memory、Function calling、Harness
2. 第 25 页：Context window 的膨胀（2k → 1M）
3. 第 26 页：Context 与 Memory——有限窗口，怎么放；大海捞针、窗口内容分层、信号与噪声、写取压忘、工作/情节/语义/程序
4. 第 27 页：Tool calling——签名、调用、沙箱执行、观察；工具输出仍是不可信输入
5. 第 28 页：Harness——权限与沙箱、超时与重试、验证与回滚、日志与停止
6. 第 29 页：把模型放回系统里（总图）；Memory 管状态，Tool calling 管计算，Harness 管验证
7. 第 30 页：Skill——触发、步骤、脚本、资产；按需加载、可版本化、可复用
8. 第 31 页：长时间运行——loop 产生经验，skill 把经验固化成下一轮可加载的流程

**过渡**：

> 这是一个具体的工程参考例子，具体科研流程由同行判断。接下来看 AI × math 的公开进展。
