# 专题：Token 到底是什么

支撑 S2–S9。这一节的目标是让听众在 9 分钟内建立可操作的 token 概念。

---

## 1. 一句话定义

> Token 是模型词表里的一个离散符号，通常对应一个子词片段，而不是一个字或一个词。

模型的处理链条：

```
文本 → 切分 → token 序列 → 整数 ID → 向量 → 模型
```

关键：**模型从不直接看字符**。它看的是 ID 和向量。

---

## 2. 为什么要切分

三种粒度各有致命问题：

| 粒度 | 词表 | 序列长度 | 问题 |
|---|---|---|---|
| 字节 | 256 | 极长 | 注意力成本爆炸 |
| 字符 | 几千 | 长 | 中文/日文等仍不理想 |
| 单词 | 百万+ | 短 | 生僻词、形态变化无法覆盖 |
| 子词 | 5 万–20 万 | 适中 | 切分不按语义 |

子词是折中：常见片段合并成一个 token，罕见片段拆成多个。

---

## 3. 主流算法

### BPE（Byte-Pair Encoding）

1. 从 256 个字节符号开始；
2. 统计语料中相邻符号对的频率；
3. 合并最高频的一对，加入词表；
4. 重复，直到达到目标词表大小。

结果：`the`、`ing`、`tion` 这类高频片段会变成单 token。

### Byte-level BPE

在字节层面做 BPE，保证任意字符串都能编码，没有 UNK。GPT-2 之后的常见选择。

### SentencePiece / Unigram

把输入当作原始字符流处理，不依赖预分词，对多语言更友好。Llama 系列常用。

### 词表大小的影响

- 词表大：序列短，但 embedding 和输出层参数多；
- 词表小：参数省，但序列长，注意力成本高。

这就是为什么不同模型的 token 数不能直接比较。

---

## 3.5 词表：模型真正的字母表

### 定义

词表（vocabulary）是一张双向映射表：

```
片段 "三"   ↔ 整数 3236
片段 " is"  ↔ 整数 382
片段 "."    ↔ 整数 13
```

两个关键性质：

1. **训练前确定，训练和推理期间都不变。**
2. **大小是一个人为选的超参数**，不是模型学出来的。

### 三个真实数字（实测）

| 编码器 | 词表大小 | 常见代际 |
|---|---|---|
| `r50k_base` | 50,257 | GPT-2 |
| `cl100k_base` | 100,277 | GPT-4 / 3.5 |
| `o200k_base` | 200,019 | GPT-4o |

### 词表里有什么

不是只有"词"：

- 词根、前缀、后缀：`ing`、`tion`、`pre`
- 带空格的片段：`" is"`、`" the"`、`" a"`
- 标点与符号：`.`、`**`、`"''"`
- 数字块：`123`、`456`
- 多语言片段：`三`、`体`、`问题`
- **特殊 token**：文本结束、对话角色、工具调用占位

特殊 token 是控制字符，不是内容；它们同样占一个 ID，也占上下文位置。

### 为什么词表大小重要

模型有两处直接依赖词表大小：

1. **输入 embedding**：`词表大小 × 维度`
2. **输出层**：对词表里每个 token 算一个分数，再做 softmax

以 20 万词表、4096 维为例：

```
200,019 × 4,096 ≈ 8.2 亿参数
```

这还没算输出层如果单独存在的情况。所以"词表大一点"不是免费的。

| 词表大 | 词表小 |
|---|---|
| 序列短、上下文利用率高 | 序列长、注意力成本高 |
| embedding / 输出层参数多 | 参数省 |
| 稀有词覆盖好 | 稀有词被拆得很碎 |

### 固定性带来的三个后果

1. **没有未登录词**：任何字符串都能拆成已知片段，不会出现 UNK。
2. **新词只能拆**：专业术语、新符号会被切成很多片，序列变长。
3. **ID 不可移植**：换模型就是换词表，同一个整数在不同模型里含义不同。

### 词表带着语料偏见

词表是从语料统计出来的，语料里多什么，词表就对什么友好：

- 英文常见词 → 一个 token
- 中文 → 取决于语料里中文占比
- 代码 → 关键字和缩进常被单独编码
- 数学符号 → `Ω`、`∂`、`∫` 的覆盖差异很大

对天体力学听众的直接含义：**同一篇论文的公式，在不同模型里 token 数可能差一倍。**

## 3.6 英文的平均长度与词表规模

### 三个经验值

| 量 | 典型值 | 说明 |
|---|---|---|
| 英文单词长度 | ≈ 5 字符 | 含空格；不含空格约 4.7 |
| token 长度 | ≈ 4 字符 | 英文普通文本 |
| token / 词 | ≈ 1.3 | 等价于 1 token ≈ 0.75 词 |

OpenAI 文档里的经验规则：**1 token ≈ 4 characters ≈ 0.75 words**（英文）。

### 本报告的例子

`Celestial mechanics is the poetry of orbits.`

- 46 字符
- 7 个单词
- 10 个 token
- 4.6 字符 / token，1.43 token / 词

比平均值略高，因为 `Celestial`、`orbits` 都被拆开了。

### 为什么选子词

| 粒度 | 后果 |
|---|---|
| 字母级 | 每个字符一个 token，序列长 4–5 倍；单字符信息量太低 |
| 词级 | 词表百万级；生僻词、形态变化、专有名词无法覆盖；输出层成本爆炸 |
| 子词 | 5–20 万，序列长度与词表大小的折中 |

### 常见词表规模

| 模型代际 | 词表大小 |
|---|---|
| GPT-2 | 50,257 |
| GPT-4 代 | 100,277 |
| Llama 3 | 128,256 |
| Qwen2.5 | 151,936 |
| GPT-4o 代 | 200,019 |

> 具体数字随 tokenizer 版本变化，报告时以官方为准。

## 5. 三个 "token"

这是报告里必须澄清的一页。

| 名称 | 英文 | 本质 | 用途 |
|---|---|---|---|
| 模型 token | model token | 序列单位 | 前向传播、上下文窗口 |
| 计费 token | billing token | 同一单位的计数 | 账单、配额、限流 |
| 认证 token | auth token / API key | 凭证字符串 | 鉴权 |

### 常见混淆

- "我的 token 用完了" → 可能是额度、速率限制、或上下文窗口，三者不同。
- "token 长度" → 指上下文窗口，不是字符串长度。
- "API token" → 在账单语境里指计费单位；在鉴权语境里指凭证。**同一个词，两个世界。**

### API 计费的几个事实

- 输入和输出分开计价，输出通常贵 3–5 倍。
- 缓存输入（prompt caching）通常更便宜。
- 上下文窗口 = 输入 + 输出的上限。
- 不同模型用不同 tokenizer，同一段文本的 token 数可能差 30% 以上。
- 价格随供应商和时间变化，报告当天必须重新核对。

---

## 6. 为什么 token 决定了很多"玄学"

| 现象 | 原因 |
|---|---|
| 数不对字母 | 它看到的是 token，不是字符 |
| 竖式加法出错 | 数字被切成不等长片段 |
| 中文比英文贵 | 切分效率不同 |
| 代码很快吃满窗口 | 空格、缩进、符号都占 token |
| 同一问题换模型表现不同 | tokenizer 与训练分布都变了 |
| 长文档效果下降 | 上下文稀释，不是"记不住" |

## 7. 实测脚本

报告前用真实 tokenizer 跑一遍，把数字写进幻灯片：

```python
# pip install tiktoken
import tiktoken

enc = tiktoken.get_encoding("o200k_base")
texts = {
    "english": "Celestial mechanics is the poetry of orbits.",
    "chinese": "天体力学是研究天体运动的学科。",
    "code": "def f(x):\n    return x**2\n",
    "numbers": "1234567890",
}
for k, v in texts.items():
    ids = enc.encode(v)
    print(k, len(ids), ids)
```

建议同时对比两三个 tokenizer（如 `o200k_base` 与某个开源模型的 tokenizer），做一张小表。这张表会成为 S6 的最强证据。

## 8. 讲稿要点（9 分钟节奏）

1. **0:00–1:00** 一句话被切成 token，展示 ID。
2. **1:00–3:00** 词表：映射表、三个大小、特殊 token、参数账。
3. **3:00–4:30** 词表怎么来：BPE 与三种粒度。
4. **4:30–6:00** 三个坑：中文、数字、代码。
5. **6:00–7:30** 三个 token 的辨析（模型 / 计费 / 认证）。
6. **7:30–8:30** token 账本：窗口、价格、缓存。
7. **8:30–9:00** 收束：token 是模型世界的像素。

---

## 9. 一句话总结

> Token 是统计上高效的切分，不是语义单位；它同时决定了模型能看见什么、你要花多少钱、以及它为什么会犯某些看起来很蠢的错。
